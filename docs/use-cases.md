# 使用场景与推荐配置

## 1. 场景速查

| 场景 | 推荐形态 | 触发语示例 | 期望产物 |
| --- | --- | --- | --- |
| 学术专著／理论书精读 | ② Agent 技能 | 「用 deep-book-reader 深度研读《xxx》，生成完整研读文档」 | 单文件全书研读文档，含机制展开与知识图谱 |
| 边读边问、逐章讨论 | ① NotebookLM prompt | 上传书 → 配好 prompt → `开始讲解` | 对话式逐章讲解，随时追问 |
| 论文／学位论文／长报告深读 | ② Agent 技能 | 「把这篇文章当作一本书来拆解，按章节生成研读文档」 | 章节化研读文档（论文结构同构可用） |
| 读书会底稿／团队共读材料 | ② Agent 技能 | 「生成整书研读文档，供读书会分发」 | 单文件，便于分发、批注、版本对比 |
| 备考与知识体系搭建 | ② Agent 技能 | 「生成研读文档并重点整理术语表与全书知识图谱」 | 附录 A 术语表 + 全书底层逻辑 |
| 只关心某一主题章节 | ② Agent 技能（限定范围） | 「只研读第 3–5 章，其余跳过」 | `## 范围总结与底层逻辑` 代替全书总结 |
| 跨语言阅读（英文学术书） | ② Agent 技能 | 「用中文输出研读文档，术语保留英文原词」 | 中文讲解 + 原术语保真 |
| 想快速看梗概 | 不适合本项目 | — | 用普通摘要工具即可 |
| 轻小说、散文随笔、操作手册 | 不适合本项目 | — | 缺少推导链条，规则显得过重 |

## 2. 场景细节

### 2.1 学术专著精读（主力场景）

- **触发**：书籍 PDF/TXT + 「深度研读，生成完整文档」
- **推荐参数**：默认（全书、逐章追加、每章 0–2 处类比）
- **产物结构**：全书导读 → 逐章板块 → 每章总结 → 全书宏观总结与底层知识图谱 → 附录 A/B/C
- **注意**：理论密度高的书膨胀比通常在 1.2–3.0；若某章明显低于 1.0，多半被摘要化了，回补该章

### 2.2 论文与长报告

- 论文的「引言—方法—结果—讨论」可以直接当作章来处理
- 图表密集时：只有图表配文字说明的部分纳入正文，纯图无文字记入附录 B
- 公式较多的部分：保留原文符号体系，首次出现给出通俗解释，不擅自改写成另一套记号

### 2.3 读书会与团队共读

- 输出是**单文件**，天然适合做讨论底稿：每人可就同一份文档批注
- 建议在元信息块注明生成方式（平台 + 模型），便于团队判断可信度
- 附录 B 是讨论富矿：里面集中列出原文的逻辑跳跃与未展开问题，正是读书会该讨论的地方

### 2.4 备考与知识体系

- 附录 A（术语表）+ 《全书宏观总结与底层知识图谱》可直接作为复习提纲
- 提示：知识图谱只整合书中已明确支持的理论，不会额外补充书外框架——需要扩展时明确要求「这部分属于我的补充，请单独标注」

### 2.5 多本书并行

- 每本书单独一个输出文件，放在 `deep-reading/` 下
- 不要让同一次任务处理多本书：章节顺序、术语体系、附录都会串味
- 需要跨书对照，请在分别生成后单独提要求，并注明哪些内容属于跨书推论

## 3. 参数速查

| 参数 | 取值 | 何时调整 |
| --- | --- | --- |
| 章节范围 | 全书 / `第 X–Y 章` | 只想读重点篇目时 |
| 输出路径 | 默认 `deep-reading/<书名>_深度研读.md` | 需要纳入既有知识库目录时 |
| 读者背景 | 默认「具备基础学术阅读能力、非本书领域的专业读者」 | 面向纯小白或同领域专家时 |
| 类比扩展 | 默认允许，每章 0–2 处 | 教材类可保留，严密理论书可要求「不使用类比」 |
| 输出语言 | 默认与书籍主语言一致 | 阅读外文书但想中文讲解时 |
| `split_book.py --budget` | 默认 40000 字/批 | 模型上下文小 → 降到 15000–20000 |
| `check_output.py --min-block-chars` | 默认 80 | 概念极短的章节可下调，机制复杂的章节可上调到 120+ |

## 4. 反面用法（会显著降低质量）

| 用法 | 后果 |
| --- | --- |
| 「给我一份 3000 字的全书总结」 | 直接触发摘要化，与项目目标冲突 |
| 「顺便补充作者的生平和这本书的历史地位」 | 违反来源忠实，模型引入书外知识 |
| 「把不同章节合并讲，按主题重排」 | 违反顺序保真，论证链条会断裂 |
| 一次任务塞进多本书 | 来源串味，附录与术语表失去意义 |
| 不核对 `manifest.json` 就交付 | 容易漏章，尤其是章节标题不规范的电子书 |

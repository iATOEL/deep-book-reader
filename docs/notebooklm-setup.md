# 在 NotebookLM 中使用（逐章模式）

面向对象：用 NotebookLM 上传书籍 PDF、希望边读边被讲解的用户。
对应文件：[`prompts/notebooklm-configure-chat.md`](../prompts/notebooklm-configure-chat.md)

## 1. 前置要求

- 一个 NotebookLM 账号与研究型 Notebook
- 书籍文件（PDF 效果最好；扫描版建议先 OCR）
- 建议 **一个 Notebook 只放一本书**：NotebookLM 的回复严格基于勾选的来源，多本书混放会让「严禁引入外部知识」这条规则失效

## 2. 配置步骤

1. 新建 Notebook，上传书籍文件，等待解析完成。
2. 在 Notebook 左侧找到 **对话设置 / Configure chat**（不同版本入口文案可能是「设置对话」「Configure chat」）。
3. 打开 `prompts/notebooklm-configure-chat.md`，**全选复制**，粘贴进设置框。
4. 保存设置。（该文件是纯 prompt 文本，没有 frontmatter 或说明段落，可整体粘贴。）
5. 在来源列表中**只勾选这本书**，然后新建一条对话。

## 3. 使用姿势

| 你的输入 | 结果 |
| --- | --- |
| `开始讲解` | 从序章或第一章开始逐板块讲解 |
| `讲解第 5 章` | 指定章节展开 |
| `继续` | 从上次截断的板块继续，不重复已讲内容 |
| `继续`（单章讲完时） | 进入下一章 |

每章讲完后会看到：

```text
【第 X / Total 章 全部讲解完毕，回复"继续"开始第 X+1 章】
```

全书讲完后会看到：

```text
【全书《书名》（共 Total 章）已全部深度拆解完毕。】
```

## 4. 逐章模式的行为边界（避免误判为「模型不听话」）

- **不做开场白**：直接输出「当前章节 / 核心主旨 / 板块」，这是 prompt 规定的格式，不是缺内容。
- **单章可能被截断**：截断是设计行为——宁可停在完整板块末尾，也不做概括式收尾。按提示回复「继续」即可。
- **不给结论清单**：输出以机制展开为主，读起来比摘要「慢」是正常的。
- **不补原文缺口**：如果书里没写中间的推导，它不会替你补，只会忠实呈现。
- **例证很少**：同一理论点默认只留 1 个例证，这是刻意的去重规则。

## 5. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 输出变成普通摘要 | 长对话后指令权重衰减 | 新开一条对话，重新发送「按 Configure chat 的规则继续讲解第 X 章」 |
| 引入了书外知识 | 勾选了额外来源，或模型自发联想 | 取消其他来源勾选，回复「删除书外内容，只保留来自原文的部分」 |
| 章节顺序错乱 | 对话中出现了让模型「总结全书」的请求 | 回到「继续」指令，按章推进 |
| 讲得太短 | 单次回复长度限制 | 回复「继续」，它会从下一个板块接续 |
| 板块编号重复 | 跨对话接续导致上下文丢失 | 明确指定「从板块 N 继续，编号延续」 |
| 书籍是扫描件，内容乱 | OCR 质量不足 | 先做 OCR 与段落校对，再重新上传 |

## 6. 已知限制

- 单次回复长度有限，长章节必然分多次讲完。
- 长对话中「不要摘要化」的指令会被稀释，建议**每讲完 2–3 章新开一条对话**，并在新对话首句重申指令。
- 输出只存在于对话中，不便于归档检索。

## 7. 想要整本一次讲完、且要一份可归档文档？

改用 Agent 技能形态：把 `skills/deep-book-reader/` 安装到 AI Agent 中，它会**一次运行产出一份完整 Markdown 研读文档**（每章板块化展开 + 每章总结 + 全书知识图谱 + 附录），并可通过脚本校验结构与覆盖率。安装方式见 [`agent-install.md`](agent-install.md)。

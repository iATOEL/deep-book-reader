# 长书分批与断点续写策略

Step 1 判定规模、Step 3 执行分批时加载本文件。

## 1. 规模判定

| 规模 | 判定 | 处理方式 |
| --- | --- | --- |
| 小（≤ 3 万字且 ≤ 6 章） | 一次可读完 | 仍按章顺序处理，逐章追加写入 |
| 中（3–8 万字或 7–12 章） | 需分批 | 每批 1–3 章，使用切分脚本生成清单 |
| 大（> 8 万字或 > 12 章） | 必须分批 | 使用切分脚本 + 断点台账，严格遵守批次顺序 |

无论规模大小，**都不得把整本书一次读入后一次性输出**——后半段必然退化为摘要。

## 2. 文本准备

| 来源 | 处理方式 |
| --- | --- |
| PDF（含文本层） | `pdftotext -layout` 或 `python -c "import fitz,sys;d=fitz.open(sys.argv[1]);print(chr(10).join(p.get_text() for p in d))" book.pdf > book.txt` |
| 扫描版 PDF | 先 OCR（平台自带 OCR 能力或 OCR 工具），再校对标点与段落边界 |
| EPUB / MOBI | 解包取 XHTML，按 `h1/h2` 转成 Markdown 标题层级 |
| TXT / MD | 直接使用；检查编码（GBK 书籍需转 UTF-8） |

转换后必做：删除页眉页脚、页码、重复书名行；保留脚注编号；确认章节标题行未被折行截断。

## 3. 切分与清单

```bash
python <skill_dir>/scripts/split_book.py "<书籍文本>" --out deep-reading/_work --budget 40000
```

- `--budget`：每批累计正文字数上限，默认 40000
- `--pattern`：自定义章节标题正则（脚本会自动识别 `第N章 / 第N节 / Chapter N / 序章 / 前言 / 附录` 等常见形式）
- `--strip-headers`：删除重复出现的页眉页脚行

产出：

- `deep-reading/_work/manifest.json`：总字数、章节数、每章字数与行号、建议批次
- `deep-reading/_work/_骨架.md`：章节清单（供人工核对章节划分是否正确）

`manifest.json` 结构：

```json
{
  "source": "book.txt",
  "total_chars": 168420,
  "chapter_count": 14,
  "chapters": [
    {"index": 1, "title": "第一章 从计数到记数", "file": "ch01.md", "start_line": 1, "chars": 11240, "batch": 1}
  ],
  "batches": [{"batch": 1, "chapters": [1, 2, 3], "chars": 32410}]
}
```

## 4. 上下文预算

| 模型上下文 | 单次读取原文上限 | 建议每批章节数 |
| --- | --- | --- |
| 32k | 约 1.5 万字 | 1 章（必要时章内再分段） |
| 128k | 约 4 万字 | 1–3 章 |
| 200k 及以上 | 约 6 万字 | 2–4 章 |

单章超过上限时，按原文小节边界切段处理；**整章所有段落处理完才写《本章总结与深度启示》**，段与段之间严禁压缩合并。

## 5. 节奏与写入规范

每章的标准节奏：

```text
读取该章原文 → 划分板块 → 逐板块展开机制 → 本章总结 → append 写入输出文件 → 更新台账 → 下一章
```

写入规则：

- 一律**追加**（append）到输出文件末尾，禁止重写整份文件
- 需要修正已写章节时，只做该章节范围内的局部替换，修正后重新运行 `check_output.py`
- 修正不得破坏板块编号连续性与章节顺序
- 长任务每完成一个批次，向用户回报一次进度（批次数 / 章节名 / 累计板块数），不粘贴正文

## 6. 断点台账与恢复

台账文件：`deep-reading/_work/progress.json`（临时工作文件，全部完成后删除）

```json
{
  "output": "deep-reading/《书名》_深度研读.md",
  "total_chapters": 14,
  "completed_chapters": [1, 2, 3],
  "next_action": "第 4 章 板块划分",
  "updated_at": "2026-10-13T10:20:00"
}
```

会话中断后恢复流程：

1. 读取 `progress.json` 与输出文件末尾，确认实际已完成到哪一章
2. 从 `next_action` 指示的位置继续，**不得重写已完成章节**，不得重复输出已写板块
3. 若输出文件与台账不一致，以输出文件实际内容为准，修正台账后继续
4. 全部章节完成 → 写全书总结与附录 → 运行校验 → 删除 `deep-reading/_work/`

## 7. 多批次质量守恒

后批次容易风格漂移，每批开始前做三件事：

1. 重读 `references/output-template.md` 的标题契约与禁止清单
2. 读取输出文件中前一批次最后一个板块的写法，保持段落粒度与标注风格一致
3. 维护术语一致性：新出现的作者术语与附录 A 中已登记术语比对，同一术语前后写法必须相同

## 8. 异常处理

| 异常 | 处理 |
| --- | --- |
| 章节划分与目录不符 | 以正文标题为准，在元信息块注明划分依据 |
| 原文存在大量重复段落（版本问题） | 按 sifting-rules 去重，并在附录 B 记录去重位置 |
| 原文缺少中间推导 | 标注 `【原文逻辑跳跃】`，不补齐，记入附录 B |
| 原文含图表 | 仅当原文有文字说明时纳入；纯图无文字时在附录 B 记录"原文图表未提供文字依据" |
| 用户中途要求限定范围 | 已完成章节保留，未读章节不写入，收尾改为 `## 范围总结与底层逻辑` |

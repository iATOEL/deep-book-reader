# Deep Book Reader（整书深度研读）

## 用途

把一本书（整本或用户限定章节）一次性生成一份可归档、可检索的单文件 Markdown 深度研读文档。

文档内部按「章 → 板块」组织：每章拆成若干逻辑板块，逐板块把定义、前提、推导机制、关键转折与边界条件讲透；每章末尾给出《本章总结与深度启示》；全书末尾给出《全书宏观总结与底层知识图谱》。

本技能是 NotebookLM 逐章交互 prompt（本仓库 `prompts/notebooklm-configure-chat.md`）的 Agent 版：研读哲学完全一致，交付形态不同。

## 与逐章交互模式的差异

| 维度 | NotebookLM prompt（逐章） | 本技能（整书） |
| --- | --- | --- |
| 交付形态 | 多轮对话 | 单个 Markdown 文件 |
| 接续机制 | 用户回复"继续" | 内部批次 + 断点续写 |
| 单次范围 | 一次一章 | 一次全书（可限定章节） |
| 篇幅控制 | 按 token 截断并标记未完 | 按章追加写入，每章自带总结 |

若用户明确要求"一章一章讲、我回复继续"的交互式陪读，改用 `prompts/notebooklm-configure-chat.md`，不要用本技能。

## 输入

必填其一（缺失时只问这一次，问清后立即开工）：

- 书籍文件路径（PDF / TXT / MD / EPUB 转换后的文本）
- 用户上传的文档
- 用户粘贴的正文

可选参数（缺失即取默认值，不得为凑参数反复追问）：

| 参数 | 默认值 |
| --- | --- |
| 章节范围 | 全书 |
| 输出路径 | `<工作目录>/deep-reading/<书名>_深度研读.md` |
| 读者背景 | 具备基础学术阅读能力、非本书领域的专业读者 |
| 类比扩展 | 允许，每章 0–2 处 |
| 输出语言 | 与书籍主语言一致（中文书 → 中文） |

## 输出契约

单文件 Markdown（UTF-8 无 BOM），结构与 `references/output-template.md` 严格一致：

- `#` 级标题全文唯一（文档标题）
- `##` 级标题：`## 全书导读`、`## 第 N 章 <章节名>`、`## 全书宏观总结与底层知识图谱`、`## 附录 X｜…`
- `###` 级标题：`### 板块 N：<核心子主题>`、`### 本章总结与深度启示`
- 板块编号每章从 1 重新开始并连续递增
- 全文禁止出现占位符（`TODO`、`待补充`、`（略）`、`受篇幅限制`、`此处省略`）
- 全文禁止出现交互模式残留（`回复"继续"`、`【第 X / Total 章未完…】`）

## 工作流

按 Step 1 → Step 5 顺序执行，不得跳步。

### Step 1｜侦察与建档

1. 定位书籍来源并确认可读。PDF 先转文本（平台自带 PDF 能力、`pdftotext` 或 `pymupdf`）；扫描件先 OCR。
2. 统计规模：总字数、章节数与章节标题清单、是否存在目录。
3. 若规模较大（> 8 万字或 > 12 章），先运行切分脚本生成章节文件与清单：

   ```bash
   python <skill_dir>/scripts/split_book.py "<书籍路径>" --out deep-reading/_work --budget 40000
   ```

   产出 `<out>/manifest.json`（每章字数、行号、建议批次）与 `<out>/_骨架.md`（章节清单）。
4. 向用户回报 3–6 行侦察结论：书名、总字数、章节数、批次计划、输出路径。随后立即开工，不要等待确认。

### Step 2｜建立文档骨架

以 `references/output-template.md` 为模板创建输出文件，先写入：

1. 元信息块（研读范围 / 来源文件 / 原文规模 / 生成时间 / 生成方式）
2. `## 全书导读`（核心论题、论证主线骨架、使用约定）
3. 各章标题 `## 第 N 章 <章节名>`

骨架阶段只写标题与导读，**不得**用"待补充""TODO"之类文字占位，也不得预写任何尚未阅读章节的结论。

### Step 3｜逐章深研并追加写入（核心循环）

对每一章按下列顺序执行，一章处理完再进入下一章：

1. **完整读取本章原文**。禁止依据目录、摘要、摘录或模型记忆推测章节内容。
2. **划分板块**：按 `references/sifting-rules.md` 的合并 / 拆分判据切分。判据不足时优先独立成板块。
3. **逐板块展开机制**：还原原文明确给出的「前提 → 推导机制 → 结论」链条，解释 A→B 的依据。原文未给出中间依据时，标注 `【原文逻辑跳跃】` 并忠实呈现，严禁自行补齐。
4. **例证极简**：每个理论点默认保留 1 个例证，最多 2 个且必须分属不同维度；承担定义、推导、反驳、思想实验或边界条件功能的例证不受此限。
5. **扩展补充**：仅在最抽象的核心概念之后附至多 1 个通俗日常类比；一章最多 2 处；无贴切类比时整个 `> 【扩展补充】` 引用块连同 `>` 一并删除，严禁写"无"。
6. **本章全部板块写完后**，才追加 `### 本章总结与深度启示`（核心逻辑链条 + 关键启示/复盘）。
7. **以追加方式写入磁盘**（append），不得重写整份文件；仅当需要修正已写章节时才做局部替换。
8. 更新断点记录（见 `references/long-book-strategy.md`）。

超长章节：按原文小节边界分段处理，各段之间不得压缩合并，整章段落全部处理完才写本章总结。

### Step 4｜全书收尾

1. 最后一章写完后追加 `## 全书宏观总结与底层知识图谱`：全书核心底层逻辑 + 知识体系应用指南（仅使用书中明确支持的理论与原则，严禁引入书外方法）。
2. 追加附录：`## 附录 A｜术语表`（作者核心术语 + 首次通俗解释）、`## 附录 B｜忠实度与未补齐清单`（汇总所有 `【原文逻辑跳跃】` 位置、原文关键弱模态表述、原文明确未展开的问题）、`## 附录 C｜覆盖率与批次记录`（各章板块数、正文字数、膨胀比、批次顺序）。
3. 若用户限定了章节范围，则第 1 步改为输出 `## 范围总结与底层逻辑`，并在元信息块标注范围；禁止伪造全书级结论或知识图谱。

### Step 5｜自检与交付

1. 运行校验脚本，按报错修正直至通过：

   ```bash
   python <skill_dir>/scripts/check_output.py "<输出文件>" --manifest deep-reading/_work/manifest.json
   ```

2. 校验通过后向用户交付：文件路径、章节/板块统计、总字数与膨胀比、校验脚本结果、附录 B 中记录的原文逻辑跳跃处数量。
3. 不要在对话中重复粘贴整篇文档；用户需要内容时给出文件路径即可。

## 硬性约束（违反即失败）

1. **来源忠实与防补齐**：所有理论、定义、论证必须来自所读原文；严禁引入外部知识（作者生平、后世评价、其他著作、外部假说）。
2. **逻辑与顺序保真**：完整覆盖本章关键概念、推导步骤与关键转折；不得改变原书论证推进顺序；不得跳章、跳节。
3. **深度优先与机制展开**：宁可在一个完整逻辑板块末尾自然结束，也绝不做概括式收尾；严禁把高密度概念串成单句结论掠过。
4. **精简去重**：合并同一理论节点的重复表述与同质例证，但不得因精简改变论证顺序。
5. **论证强度保真**：原文"可能、倾向于、似乎、意味着、推测"等弱模态不得改写为"必然、一定、证明、终将"；原文强结论也不得擅自弱化。
6. **术语保真**：保留作者核心术语，首次出现用通俗语言解释，不得用自造概念体系替换。
7. **推论标注**：属于研读者基于文档的推论必须标注 `【基于文档的推论】`，不得写成本书明确提出的观点。
8. **严格格式**：严格遵守输出契约与模板，禁止开场白、问候语、废话。

## 失败模式（自检）

| 症状 | 处理 |
| --- | --- |
| 一次读完整本书再一次性输出 | 上下文溢出，后半段退化为摘要。改为按章分批 |
| 输出"作者认为…"式结论罗列 | 违反深度规则，回到该板块补机制展开 |
| 写"其余章节脉络类似""篇幅所限" | 直接失败，必须逐章完整覆盖 |
| 引入书外知识或补齐原文缺口 | 直接失败，删除补写内容，改为标注 `【原文逻辑跳跃】` |
| 章节标题与原文不一致 | 回到原文核对标题后修正 |
